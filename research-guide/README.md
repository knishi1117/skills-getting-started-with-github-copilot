# お仕事の進め方ガイド（試作版）

公開情報を使って業界動向などを定期的に調査・報告する管理職向けの試作です。困りごとを選ぶと、次に試せる行動、生成AIに渡す指示文、回答を見るポイントが表示されます。

- 静的ファイル3点（`index.html` / `app.js` / `styles.css`）だけで動きます。ビルドも追加の依存関係もありません。
- このリポジトリの既存アプリ（`src/`、FastAPI）とは独立していて、既存ファイルは変更していません。

## 起動方法（ローカル）

```sh
python3 -m http.server 8123 --directory research-guide
# http://localhost:8123/index.html を開く
```

どの静的ホスティング（GitHub Pages など）でも配信できます。指示文の自動コピーには HTTPS か localhost が必要です。それ以外の環境では、手動でコピーする案内に切り替わります。

## 画面構成

トップ → カテゴリ → 困りごと → 実用カード の順に進みます。

| 画面 | 内容 |
| --- | --- |
| トップ | 「今日は、どのお仕事を進めますか？」、2つのカテゴリ、両カテゴリをまとめたお気に入り（所属カテゴリを併記）、「有料でできること（準備中）」へのリンク |
| カテゴリ：情報収集・報告書づくり | 「お仕事で、どこに迷っていますか？」と4つの困りごと、補助導線の「5問のチェック」、保存した結果 |
| カテゴリ：Excel作業 | 4つの困りごと（関数・数式のエラー・集計・表の見た目）。診断はありません |
| 選択式ガイド（計8本） | 6ステップ：①状況を選ぶ ②進め方と指示文を見る ③普段の生成AIで試す ④見本と確認ポイントを見る ⑤気になる点を選び、修正方法を確認する ⑥最後のチェック。各ステップへ直接移動できる。詳しくは下の「選択式ガイド」 |
| 5問のチェック | 目的・問い・情報整理・根拠確認・骨子から1問ずつランダム出題（開始時に固定）、進捗表示、前の質問に戻れる |
| 結果 | 見出し「次のお仕事で試せそうなこと」、提案、ほかの候補、これから試せるヒント、注記。保存は本人が選んだときだけ |
| 有料でできること（準備中） | 構想の紹介（条件に合わせた作業ガイド、追加カテゴリ）と、無料機能との違い。購入・会員登録・アンロックはなく、価格や提供時期も記載しない |
| 端末内の記録について | 保存内容、同期できないこと、公開環境のログは確認中であること、まとめて削除 |

カードのIDは以前の版から変えていないため、以前に保存したお気に入り・記録・診断結果はそのまま使えます（`schemaVersion` 1 の保存データも読み込めます）。

### お仕事の木

トップのカテゴリ選択の下に、小さなカードで表示します。ガイドを主役にした補助的な表示で、能力やスキルの評価ではありません。

| 操作 | 木への反映 | 回数 |
| --- | --- | --- |
| 「水をあげる」（その日初めての訪問で表示） | 水滴と「今日も、あなたのペースで。」を表示。成長段階は進まない | 1日1回 |
| ガイドの「試してみた」 | 葉が1枚増える。もう一度押すと今日の分を取り消し、葉も戻る | 同じガイドは1日1回 |
| ガイドのステップ4「確認ポイントを見直した」 | 花が1つ増える | 同じガイドは1日1回 |

- 木の姿は、試した日数（同じ日に複数のガイドを試しても1日）で変わります：苗木（0日）、小さな木（1〜2日）、枝が伸びた木（3〜6日）、葉が広がった木（7日以上）。試作の演出用ルールで、`app.js` の `TREE_RULES` で変えられます。
- 絵に描くのは葉12枚・花6輪までで、それ以上は「成長の記録を見る」の数字で示します。
- 日付は端末のローカル日付です。連続訪問ボーナス、ランキング、枯れる表現、休んだときの警告はありません。
- ガイドを完了したときも、その日の「試してみた」として記録します（同じ日・同じガイドなら増えません）。

### 選択式ガイド

| ID | ガイド | ①で選ぶ状況 |
| --- | --- | --- |
| `scope` | 調べたいことが、うまくまとまらない | 目的・対象期間・相手（それぞれ「未定」あり） |
| `organize` | 情報が多くて、整理できない | 分類したい／報告に使う情報を選びたい／不足や重複を見つけたい |
| `refine` | AIの回答が、しっくりこない | 一般論が多い／欲しかった答えと違う／根拠が分からない |
| `outline` | 報告書の流れが、決まらない | 目的・相手・長さ |
| `excel-function` | 使いたい関数が、分からない | 判定／検索／集計／文字や日付／どれか分からない |
| `excel-error` | 数式のエラーを、解消したい | エラー表示が出る／表示はないが結果がおかしい／原因が分からない |
| `excel-aggregate` | 集計の進め方に、迷っている | 合計・件数・平均・未定、一度だけ・繰り返し |
| `excel-format` | 表を見やすく、整えたい | 確認・比較・入力・印刷 |

- 指示文は各カードの確定文面をそのまま先頭に置き、選んだ状況に応じた指示を後ろに足します。「未定」や未選択の条件は「仮置き」と明記します。状況を変えると指示文が更新され、画面で知らせます。前回コピーした後に変えた場合は、もう一度コピーするよう案内します。
- 「AIで試す」は自動送信ではなく、コピーと手順の案内だけです。AIの回答や資料をアプリに入力する必要はありません。
- ④の見本はすべて架空の例です。Excel の見本（検索・エラー・集計）は小さな架空の表を LibreOffice 24.2 で再計算し、結果を確かめています（XLOOKUP は LibreOffice 24.2 にないため、見本の計算は VLOOKUP と IFNA で確認し、XLOOKUP は書き方の紹介にとどめています）。
- ⑤の気になる点には、必ず「問題なし」（例：この問いで進められそう）と「まだ判断がつかない」があります。「まだ判断がつかない」では、見る場所を具体例で示します。修正しなくても④から⑥へ進み、そのまま完了できます。
- ⑥で完了すると、そのガイドの進み具合を消し、「試してみた」を記録します（感想は任意）。
- 内容は `app.js` の `GUIDES` にまとめています。

### 結果の分岐（`computeResult`）

1. 「まだあまりしていない」の分野を表示順で提案。なければ「そうすることもある」の分野から提案。
2. 「今は思い浮かばない・経験がない」は低評価に含めず、「これから試せるヒント」として別に表示。
3. 全回答が未経験 → 目的のヒントから案内。
4. 全回答が「普段からそうしている」 → 進め方を振り返る確認リスト。
5. 「普段から」と「未経験」だけの場合 → 未経験分野のヒントを表示順で案内。
6. 未回答の設問があるときは先に進めず、エラーを表示。

総合点、順位、能力判定、前回との比較は表示しません。根拠確認は専用の出典確認ヒントだけを表示し、指示文は付けません。

## プライバシーと通信

- 生成AIのAPI連携、登録、ログイン、決済、アクセス解析、広告タグ、外部フォント、外部埋め込みはありません。
- 入力欄は回答用の選択肢（ラジオボタン）だけです。氏名・メール・会社名・自由記述・ファイルアップロードの入力欄はありません。
- `Content-Security-Policy` で `connect-src 'none'` などを指定し、通信と外部リソースの読み込みをブラウザー側でも禁止しています。
- 画面の切り替えで URL は変わりません。`history.state` には画面名・カードID・設問番号だけを入れ、回答内容は入れません。

### 端末内に保存するデータ（localStorage キー `research-report-guide`）

```json
{
  "schemaVersion": 3,
  "favorites": ["organize", "excel-error"],
  "practice": { "organize": { "tried": true, "feedback": "helpful" } },
  "latestResult": { "questionIds": ["A1", "B3", "C2", "D1", "E2"], "answers": { "purpose": "notyet" }, "savedOn": "2026-10-28" },
  "progress": { "outline": { "step": 3, "sel": { "purpose": "proposal" }, "issue": null, "checks": [], "touched": 4 } },
  "seq": 4,
  "tree": {
    "lastWatered": "2026-11-03",
    "practiced": [{ "date": "2026-11-03", "id": "organize" }],
    "reviewed": [{ "date": "2026-11-03", "id": "outline" }]
  }
}
```

- `tree` はお仕事の木の記録です（最後に水やりした日、「試してみた」を押した日とガイド、見直した日とガイド）。同じ日・同じガイドは1件だけ保存し、読み込み時にも重複や不正な日付を取り除きます。
- `practice` は「試してみた」の有無と感想、`tree.practiced` はその日付の記録です。日付の記録は `tree.practiced` だけに持ち、二重に管理しません。以前の版で記録した「試してみた」には日付がないため、`undated: true` を付けて残し、日付を推測して木に数えることはしません。
- `progress` はガイドごとの進み具合（表示中のステップ、選んだ状況、気になる点、確認リストの印）です。操作したときだけ保存し、`touched` が最大のものをトップの「前回の続きから」に表示します。完了するとそのガイド分を消します。日時は保存しません。
- 読み込み時に検証し、想定外の値は捨てます。データが壊れているときや localStorage が使えないときも、カードの閲覧と診断はそのまま使えます（画面上に案内を表示）。
- 別の端末への同期や復元はできません。

## Cloudflare Pages で公開する

静的ファイルだけのサイトです。サーバー側の処理（Pages Functions）、API、ログイン、アクセス解析は使いません。

### 公開用のファイル

- `build.sh`：公開するファイル（`index.html`・`app.js`・`styles.css`・`_headers`）だけを `dist/` にコピーします。依存関係のインストールやダウンロードはしません。README やテストは公開しません。
- `_headers`：Cloudflare Pages が付ける HTTP ヘッダーです。`index.html` の meta と同じ CSP に `frame-ancestors 'none'` を加え、`Referrer-Policy: no-referrer` などを指定し、既定の `Access-Control-Allow-Origin: *` を外します（このファイル自体は配信されません）。
- `index.html` は `/app.js`・`/styles.css` を絶対パスで読み込みます。Cloudflare Pages は `404.html` がない場合、存在しないパスにも `/` を返すため、どのURLで開いてもアプリが正しく読み込まれます。

### 管理画面で設定する値

| 項目 | 値 |
| --- | --- |
| 連携するリポジトリ | `knishi1117/skills-getting-started-with-github-copilot` |
| 本番ブランチ | アプリが入っているブランチ（2026-11 時点では `claude/manager-research-report-app-c0hac6`。`main` にはまだ入っていません） |
| フレームワークのプリセット | なし（None） |
| ルートディレクトリ | `research-guide` |
| ビルドコマンド | `sh build.sh` |
| ビルド出力ディレクトリ | `dist` |
| 環境変数 | 不要（秘密情報も不要） |

- ルートディレクトリを `research-guide` にするのは、リポジトリ直下にある既存の FastAPI 用の `requirements.txt` などを、ビルドの対象にしないためです。
- 出力ディレクトリがルートディレクトリから見た位置として扱われることは、公式文書に明記がありません。初回のビルドログで `dist` が見つからない場合は、`research-guide/dist` に変えてください。

### 公開前に確認すること

- **Web Analytics を有効にしない**：プロジェクトの **Metrics** にある Web Analytics を有効にすると、Cloudflare が次回のデプロイから計測用の JavaScript を自動で追加します。このアプリでは有効にしません（追加されても CSP で読み込みを止めます）。
- **プレビューのデプロイ**：既定では本番以外のブランチへのプッシュごとに、公開URL（`*.pages.dev`）付きのプレビューが作られます。不要なら **Settings** → **Builds & deployments** → **Preview branch** を **None** にします。

### Cloudflare 側の処理と、アプリの送信の違い

- **アプリ**：診断の回答、実践記録、ガイドの進み具合、お仕事の木の記録は、ブラウザーの localStorage にだけ保存し、どこにも送信しません。CSP の `connect-src 'none'` で、通信そのものをブラウザーが止めます。ブラウザーが受け取るのは `/`・`/app.js`・`/styles.css` の3つだけで、URL やリクエストに入力内容は入りません。
- **Cloudflare**：ページを配信する事業者として、閲覧のたびに通常のHTTPリクエスト（接続元IPアドレス、日時、要求したパス、User-Agent など）を受け取ります。これはどの公開サーバーでも起きることで、アプリの設定では止められません。Cloudflare が何を記録し、どれだけ保存するかは Cloudflare のプライバシーポリシーと契約条件によります（未確認）。

## 公開環境のアクセスログ（2026-10-28 時点の調査）

### 実際のホスティング設定
- このアプリは、まだどこにも公開していません。リポジトリの GitHub Pages は無効です（GitHub API の `has_pages: false`）。デプロイ用のワークフローや、Netlify・Vercel などの設定ファイルもありません。
- そのため「公開環境で何が記録されるか」は、公開先を決めるまで確定できません。

### ローカルで動かす場合（README の起動方法：`python3 -m http.server`）
Python 標準ライブラリのソース（`BaseHTTPRequestHandler.log_message`）と、実際の出力で確認しました。
- 記録される項目：接続元IPアドレス、日時、リクエスト行（例：`GET /app.js HTTP/1.1`）、ステータスコード
- 保存期間：ターミナル（標準エラー出力）に表示されるだけで、ファイルには保存されません（出力をファイルへ転送した場合を除く）
- 無効化：起動オプションはありません。出力を捨てれば記録は残りません（例：`2>/dev/null`）
- アプリは URL にクエリや入力内容を付けないため、リクエスト行に診断の回答や記録は含まれません（e2e テストで確認）

### GitHub Pages で公開する場合（公式ドキュメント）
- 記録される項目：「サイトが閲覧されると、訪問者が GitHub にサインインしているかどうかにかかわらず、訪問者のIPアドレスがセキュリティ目的で記録・保存される」（github/docs `what-is-github-pages.md`）。GitHub のプライバシーステートメントには、サービス利用情報として IPアドレス、デバイス情報、リクエストの日時などを収集するとの記載があります。ただし、Pages の訪問者に対して、IPアドレス以外のどの項目を記録するかは明記されていません → **IP以外の項目は未確認**
- 保存期間：プライバシーステートメントは「保存期間は収集目的と法的義務によって異なる」とするだけで、具体的な日数の記載はありません → **未確認**
- 無効化：上記ドキュメントに、サイト所有者が記録を止める設定の記載はありません。止められないことを示す明確な記載もないため → **未確認**（GitHub サポートへの問い合わせが必要）
